- Infra/security · **Compose-native first-run secrets and TLS (ADR 0007)** — `git clone` plus `docker compose -f compose.yaml -f infra/compose.proxy.yaml up -d` is now a complete install on any platform, with no `.env` and no host bootstrap script. (Those two `-f` flags are required: `proxy` is defined only in the overlay, so the bare `docker compose up -d` brings up the API without the TLS/UI edge.) A new one-shot `secrets` service (`scripts/bootstrap_secrets.py`; `network_mode: none`, every capability dropped except `CHOWN`, read-only rootfs) runs before the gateway, the workers and the proxy (`depends_on: service_completed_successfully`) and generates, once, the worker key, the master key, the local WebUI key (`webui-local`, registered by SHA-256) and a loopback TLS certificate into `certs/`. Precedence is contractual: an explicit environment value always wins, an existing file is never overwritten (so re-running `up -d` cannot rotate a key out from under a running stack), and `REQUIRE_PROVIDED_CERTS=1` restores strict fail-closed behaviour — nothing is generated, a missing pair refuses to start, and a certificate this project generated is refused because it carries `certs/.generated-by-voxi`. Generated files are root-owned with no world access (`0600 root:root` where the only reader is the root proxy — `webui.key`, `certs/voxi.key` — and `0640 root:voxi` where the reader is the UID 10001 runtime, the honest equivalent of "root-only" for a non-root reader); no value is printed, logged or placed in a container environment. New secret-source seam `src/voxi/secrets.py` (`environment → <NAME>_FILE → VOXI_SECRETS_DIR/<file>`) is wired into the gateway `Settings`, `worker_auth`, the worker startup guard and `scripts/smoke.py`; the proxy entrypoint reads `webui.key` from the shared read-only volume when `VOXI_WEBUI_KEY` is empty and refuses generated material in strict mode. The generated keyring is self-healing: if the local WebUI key is later pinned in the environment, the derived `webui-local` record is refreshed (other records kept) instead of silently 401ing every injected call — no key is rotated. `tests/test_secrets.py` (22 cases) locks precedence, idempotency, the keyring hash, log-silence, permissions, SANs and every strict-mode refusal; the whole contract was also exercised live — inside the real image for generation/modes/idempotency/strict mode, against the real nginx image for the entrypoint guards, and end-to-end on a simulated fresh clone (no `.env`, no `certs/`) for install, idempotency, user-certificate precedence and full restore.

- Infra/security · Turnkey local identity through the TLS proxy (**ADR 0006**). The nginx proxy (`infra/compose.proxy.yaml`) is now the single published service and, on one local machine, makes the WebUI usable with **no key entry**: it injects a **separate, revocable** local key (`VOXI_WEBUI_KEY`, registered in `VOXI_API_KEYS_JSON` as `webui-local` — never the master `VOXI_API_KEY`) into same-origin `/v1` calls. The "loopback keyless" hole (another browser page DNS-rebinding into `127.0.0.1`) is closed at the vhost: a foreign `Host` → **421**, a cross-site request (`Origin` / `Sec-Fetch-Site: cross-site`) → **403** before any injection, and **no CORS is ever advertised**. `integrations/nginx/voxi-entrypoint.sh` enforces the invariants at container start (refuses to boot keyless injection against a non-loopback bind, and refuses to boot without TLS), so editing `.env` cannot bypass them; `nginx.conf.template` renders only three variables into a `0600` root-only config, `log_format voxi_safe` records `$uri` only and `error_log` is pinned to `warn`, so the bearer never reaches a log. `-ExposeLan` is an explicit **different** mode: injection off, guards off, every client supplies its own key over TLS (LAN never runs plaintext). New `pwsh infra/bootstrap.ps1` is idempotent (treats empty/`change-me` as absent, never overwrites a real secret, writes `.env` owner-only via `icacls`/`600`, generates a self-signed cert, registers/rotates `webui-local`, and only prints the key on `-ShowKey`; `-RotateKey` revokes). - F5 security · Short-lived, single-use WebSocket handshake ticket: new `POST /v1/auth/socket` (Bearer-authenticated, body `{scope ∈ audio:write|audio:read|realtime:connect}` → `201 {ticket, expires_in}`). `authorize_socket()` now prefers `?ticket=<opaque>` on every WS route (`/v1/tts/stream`, `/v1/realtime/transcriptions`, `/v1/sessions/{id}/stream`) and consumes the ticket on first use. ## 0.2.0 — Bounded streaming media slice

- `WS /v1/tts/stream`: platform-specific streaming synthesis (`speak` request, `meta` frame, 4-byte `>HH`-framed PCM16, `done`/`cancelled`/`error`), chunk-boundary cancellation, reusable connection and a bounded outbox that applies backpressure instead of buffering without limit.
- `WS /v1/realtime/transcriptions`: windowed near-real-time transcription with `session.start` handshake, `session.started`/`speech.started`/`transcript.partial`/`transcript.final`/`speech.ended`/`error`/`session.ended`, monotonic per-utterance revisions, per-socket audio budget and `flush`/`ping`/`session.stop` control frames. Partial results are real bounded STT worker calls, not token streaming, and no OpenAI Realtime compatibility is claimed.
- Internal TTS worker `POST /internal/speech/stream` emits headerless `pcm_s16le` with engine/sample-rate/generation metadata; the inference slot is reserved before response headers, so a saturated worker returns a true 429 rather than a truncated stream, and is released exactly once from the stream's `finally`.
- Energy-VAD `SpeechEndpointer` (20 ms RMS windows, open/close hysteresis, start/end/min-speech timing, preroll, hard `max_utterance_ms` bound) drives session turn detection, false-start suppression and automatic barge-in; explicit `barge_in`/`turn` control frames remain supported.
- Session stream playout now interleaves audio and control events on one ordered queue, so `clear` can never be overtaken by interrupted-generation audio, and teardown drains queued frames instead of dropping the last event.
- Inbound utterances are wrapped in a RIFF WAV container before reaching the STT decoder; bare PCM is never handed to FFmpeg.
- New stream/VAD settings validated at startup: `VOXI_STREAM_SAMPLE_RATE`, `VOXI_TTS_CHUNK_MS`, `VOXI_WS_IDLE_TIMEOUT`, `VOXI_STREAM_STT_TIMEOUT`, `VOXI_VAD_START_MS`, `VOXI_VAD_END_MS`, `VOXI_VAD_MIN_SPEECH_MS`, `VOXI_VAD_OPEN_RMS`, `VOXI_VAD_CLOSE_RMS`.
- Contracts exported from strict pydantic models; every outbound WebSocket frame is validated before send. Documentation, ADR 0005 amendment and compatibility table updated.
- Pinned `websockets` as a runtime dependency: Uvicorn has no built-in WebSocket protocol, so without it every streaming upgrade is silently refused while in-process `TestClient` tests stay green.
- Fixed connection-admission accounting: streaming loops no longer charge each audio chunk to the per-key rate limit, so one legitimate stream cannot lock its own key out of the next connection.
- Added `scripts/smoke_stream.py`, a live raw-WebSocket client proven against a real uvicorn server (transport refusal, meta→framed-audio→`done` ordering, truthful duration, connection reuse, chunk-boundary cancel and the windowed transcription handshake). Corrected the documented handshake-rejection behavior: pre-`accept()` closes are an HTTP 403 upgrade refusal, not WebSocket close codes.
- Still unqualified: SIP/RTP, DTMF, real transfer execution, measured first-audio/end-of-turn latency, concurrent-call capacity and any OpenAI Realtime emulation.
