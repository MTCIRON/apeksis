# Code of Conduct

## The short version

Be serious and be decent. This project exists because a certain kind of rigour matters
(measured claims, honest limits, reproducible builds); the same rigour applies to how people
are treated here.

## Scope

This applies inside the repository (issues, discussions, pull requests, code review) and in
connected project spaces: the bundled documentation, the WebUI community surfaces and
representative spaces for the project. It also applies when representing the project
elsewhere.

## Expected of everyone

- **No fabricated evidence.** Never present a timing, benchmark, transcript, screenshot or
  "test result" that did not happen on real hardware. State what you measured, on what, and
  what you did not. Corrections are welcome; inventions are not.
- Critique code, designs and claims — not the person. Turkish and English are both welcome;
  write to be understood.
- Assume honest intent in disagreement ("the benchmark disagrees with you" is a technical
  claim, not an attack), and update your position when the evidence does.
- Keep reproduction data clean: no personal transcripts or others' recordings in issues; blur
  anything you would not publish yourself. This is a voice product — treat audio of real
  people as sensitive by default.
- Do not demand free work. Ask specific questions after you have done the error output,
  command and documentation reading the docs ask for.

## Unacceptable

Harassment, insults, discrimination, sexualised language, doxxing, publishing others' private
information or recordings, sustained disruption of discussions, and intimidation of newcomers.
Advocating for or contributing code that deceives users (fabricated provenance, fake
benchmark UI) falls under this as well.

## How reports work

Report privately — do not litigate a conduct matter in a public thread. Use GitHub's private
channels: a direct message to the maintainer on GitHub, or an issue marked and requested for
private triage where the platform allows it. If the repository has not been published yet,
conduct cannot be reported — there is no private inbox before that point. The maintainer
(currently the project owner) reviews reports, keeps them confidential, and can:

1. ask for a private correction, 2. reject contributions from the account, 3. remove content,
4. block the account from the project's spaces.

Nothing here restricts anyone from saying what the code actually does. Publications of
obvious defects remain protected speech; the only thing asked is that they be *real*.
